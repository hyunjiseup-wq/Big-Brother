# 미전송 검수 조회 개선 — 2026-09-30

기준 커밋: `51bf88e`. 관리자 수동 검수 정책과 자동 시작 미등록 방침은 변경하지 않았다.

## 확인한 문제

- 기존 `!BB 검토대기`의 미전송 조회는 최근 168시간, 최대 15건으로 제한됐다.
  따라서 DB에는 기록이 있어도 7일 이상 경과한 대기 검수를 명령으로 발견하기 어려웠다.
- 조회된 목록 길이를 건수로 표시하여 미전송 대기가 15건보다 많으면 전체 건수로 오해할 수 있었다.
- 안내문이 모든 항목을 자동 타임아웃 적용 건처럼 설명하여 수동 검수 운영 체제와 혼동될 수 있었다.
- 긴 사유와 조치 설명을 여러 건 표시하면 Discord 임베드 길이 제한을 넘을 수 있었다.

## 개선 사항

- 전체 기간의 `pending + card_delivered=0` 기록에 대한 읽기 전용 페이지 조회를 추가했다.
  서버 범위를 분리하고, 생성 시각/검수 ID 순으로 오래된 항목부터 정렬한다.
- 전체 건수와 페이지 항목은 하나의 SQLite 읽기 트랜잭션으로 조회한다.
  조회용 부분 인덱스를 추가했으며 다음 정상 `init_db()` 시 생성된다.
- `!BB 검토대기`는 기간 제한 없는 미전송 전체 건수와 오래된 5건을 보여준다.
  중단 의심 목록은 조회 상한을 명시하고, 안내를 수동 검수 운영에 맞게 고쳤다.
- `!BB 미전송검수 [페이지]`를 추가했다. 서버 내 관리자만 호출할 수 있으며 상세 목록은
  관리자 DM으로만 전송한다. 5건씩 검수 번호·사용자/채널 ID·감지 시각·원문 링크·사유 요약을 표시한다.
- DM 실패 시 공개 채널에는 일반 오류 안내만 게시한다. 멘션 호출도 비활성화했다.
- 잘못된 페이지, 범위 초과, 비어 있는 목록, 원문 메시지 ID 없음 상태를 구분한다.
- 긴 사유와 레거시 조치 설명을 제한하여 임베드 필드 및 전체 길이 제한을 지킨다.
- README·재검사 운영 문서와 `bot.py`의 오래된 자동 제재 설명을 현재 체제에 맞춰 갱신했다.

새 조회는 제재·카드 재전송·상태 변경·학습·기록 삭제를 하지 않는다. 미전송 표시와 실제
카드 존재 여부가 다를 수 있으므로 기존 카드와 검수 번호를 먼저 대조해야 한다.
다른 관리자가 목록을 처리하면 다음 페이지 구성이 달라질 수 있으며 이를 DM에 안내한다.

## 운영 영향과 남은 내용

- 실제 Discord DM 전송은 테스트 대역으로 검증했다. 운영 봇 시작 후 관리자 DM 수신 설정에
  따른 실제 전달 확인은 남아 있다.
- 로컬 인스턴스 잠금 조회 결과 봇은 중지 상태다. 이번에 봇을 시작·재시작하지 않았다.
- 운영 DB 마이그레이션·데이터 삭제·제재·대시보드 재배포는 실행하지 않았다.
- 카드 재게시 기능은 추가하지 않았다. 상태 표시만 믿고 재전송하면 중복 카드가 생길 수 있으므로
  실제 카드 대조와 검수 상태 확인을 포함한 별도 복구 흐름이 필요하다.
